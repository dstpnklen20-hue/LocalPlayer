# ТЗ: Android-плеер для локальной музыки

Oct 5, 2026 · @Leonid

## 1. Назначение

Нужно создать нативное Android-приложение «Музыкальный плеер» (рабочее название **LocalPlayer**), которое находит аудиофайлы в памяти телефона или планшета и воспроизводит их без интернета. Никаких стримингов, аккаунтов и серверов.

Документ написан как задание для AI-ассистента с доступом к коду (Claude Code). Работать по этапам из раздела 8: после каждого этапа проект должен собираться и запускаться.

Правила для исполнителя:

- Интерфейс приложения — на русском языке (строки только в `strings.xml`, чтобы потом можно было добавить английский).
- Комментарии в коде — на русском, коротко, там где логика неочевидна.
- Не добавлять функции из раздела 9, пока не готов MVP.
- Если требование неоднозначно — выбрать самый простой вариант и оставить `// TODO` с пояснением.

## 2. Стек и окружение

Язык — Kotlin, UI — Jetpack Compose, воспроизведение — AndroidX Media3 (ExoPlayer + MediaSession). Версии библиотек брать актуальные стабильные на момент сборки и фиксировать в `gradle/libs.versions.toml`.

| Компонент | Выбор | Зачем |
| --- | --- | --- |
| Язык | Kotlin | Стандарт Android-разработки |
| UI | Jetpack Compose + Material 3 | Декларативный UI, динамические цвета (Material You) |
| Навигация | Navigation Compose | Переходы между экранами |
| Плеер | Media3 ExoPlayer | MP3, FLAC, AAC, OGG, WAV, gapless |
| Фон и уведомления | Media3 `MediaSessionService` | Контролы в шторке, на экране блокировки, в наушниках |
| Поиск файлов | `MediaStore.Audio` | Системный индекс музыки, без ручного обхода папок |
| База данных | Room | Плейлисты, избранное, счётчик прослушиваний |
| Настройки | DataStore (Preferences) | Тема, сортировка, последний трек и позиция |
| DI | Hilt | Простое внедрение зависимостей |
| Обложки | Coil | Загрузка и кэш обложек альбомов |
| Асинхронность | Coroutines + Flow | Реактивное обновление списков |

Параметры проекта:

- `minSdk` = 26 (Android 8.0), `targetSdk` и `compileSdk` = последний стабильный API.
- Package name: `com.localplayer.app` (можно поменять перед стартом).
- Сборка: Gradle Kotlin DSL, version catalog, один модуль `app`.
- Проект должен открываться и собираться в Android Studio без ручных правок (`./gradlew assembleDebug`).

## 3. Функциональные требования (MVP)

MVP = найти всю музыку на устройстве, удобно её листать и слушать в фоне, включая плейлисты. Каждый пункт имеет код для ссылок из раздела 8.

### 3.1. Библиотека

- **F1. Сканирование.** Через `MediaStore` получить все треки с `IS_MUSIC = 1`. Поля: id, название, исполнитель, альбом, albumId, длительность, номер трека, год, путь к папке, дата добавления, content URI.
- **F2. Фильтр коротких файлов.** По умолчанию скрывать треки короче 30 секунд (звонки, голосовые). Порог меняется в настройках.
- **F3. Автообновление.** Подписаться на `ContentObserver` MediaStore; плюс pull-to-refresh на экране библиотеки.
- **F4. Вкладки:** Треки, Альбомы, Исполнители, Папки, Плейлисты.
- **F5. Сортировка** треков: по названию, исполнителю, альбому, дате добавления, длительности; по возрастанию/убыванию. Выбор сохраняется.
- **F6. Поиск** по названию, исполнителю и альбому, без учёта регистра и букв ё/е, результаты сгруппированы по типу.
- **F7. Быстрая прокрутка** по алфавиту (буквенный индекс справа) в списке треков и исполнителей.

### 3.2. Воспроизведение

- **F8.** Тап по треку запускает его, а очередью становится текущий список (альбом, папка, плейлист, результат поиска).
- **F9.** Плей/пауза, следующий, предыдущий (если прошло > 3 с — в начало трека), перемотка ползунком.
- **F10.** Перемешивание (shuffle) и повтор: выкл / вся очередь / один трек.
- **F11. Очередь:** просмотр, «Играть следующим», «Добавить в очередь», удаление свайпом, перетаскивание для смены порядка.
- **F12. Восстановление сессии:** после перезапуска приложения показывается последний трек, позиция и очередь (на паузе, без автозапуска).
- **F13. Таймер сна:** 15 / 30 / 45 / 60 минут или «до конца трека»; за 10 с до остановки — плавное затухание.

### 3.3. Плейлисты и избранное

- **F14.** Создание, переименование, удаление плейлистов (хранятся в Room, по id трека из MediaStore).
- **F15.** Добавление трека / альбома / папки в плейлист через меню «⋮»; смена порядка перетаскиванием.
- **F16.** «Избранное» — системный плейлист, кнопка-сердечко на экране плеера.
- **F17.** Автоплейлисты: «Недавно добавленные» (последние 30 дней), «Часто слушаю» (топ-50 по счётчику). Прослушивание засчитывается после 50% длительности.

### 3.4. Действия с треком (меню «⋮»)

- **F18.** Играть следующим, в очередь, в плейлист, перейти к альбому / исполнителю, «Подробнее» (формат, битрейт, размер, путь), «Поделиться» (файл через системный share sheet).
- **F19.** Удаление файла с устройства — только с подтверждением через системный диалог `MediaStore.createDeleteRequest` (Android 11+).

### 3.5. Настройки

- **F20.** Тема: системная / светлая / тёмная; динамические цвета вкл/выкл (Android 12+).
- **F21.** Порог коротких файлов (F2) и список исключённых папок (например, `WhatsApp/Media`).
- **F22.** Пауза при отключении наушников (вкл по умолчанию); возобновление при подключении Bluetooth (выкл по умолчанию).
- **F23.** «О приложении»: версия, список лицензий библиотек.

## 4. Экраны и интерфейс

Стиль — Material 3, спокойный и современный. Нижняя панель навигации + мини-плеер над ней на всех экранах библиотеки.

| Экран | Содержимое | Требования |
| --- | --- | --- |
| Онбординг / разрешение | Пояснение, зачем нужен доступ к аудио, кнопка «Разрешить» | При отказе — кнопка «Открыть настройки» |
| Библиотека | Верхние вкладки: Треки / Альбомы / Исполнители / Папки | Свайп между вкладками (HorizontalPager), кнопки поиска и сортировки в шапке |
| Список треков | Обложка 48 dp, название, исполнитель · длительность, «⋮» | Играющий трек подсвечен; долгое нажатие = множественный выбор |
| Альбомы | Сетка 2 колонки (планшет — 4+), обложка, название, исполнитель | Пустая обложка — заглушка с иконкой ноты |
| Альбом / Исполнитель / Папка | Шапка с обложкой, кнопки «Играть» и «Перемешать», список треков | Альбом — по номеру трека; папки — деревом с вложенностью |
| Плейлисты | Автоплейлисты сверху, ниже пользовательские, FAB «+» | Редактирование порядка перетаскиванием |
| Поиск | Поле ввода с автофокусом, группы Треки / Альбомы / Исполнители | Debounce 300 мс |
| Мини-плеер | Обложка, название, исполнитель, плей/пауза, следующий, тонкая полоса прогресса | Тап или свайп вверх — полный плеер |
| Полный плеер | Большая обложка, название, исполнитель, ползунок с временем, контролы, shuffle, repeat, сердечко, таймер, очередь | Фон — цвет, взятый из обложки (Palette); свайп вниз — свернуть; свайп по обложке — следующий / предыдущий |
| Очередь | Bottom sheet со списком | Перетаскивание, свайп-удаление |
| Настройки | Пункты F20–F23 | Открывается из шапки библиотеки |

Нижняя навигация: **Библиотека · Плейлисты · Поиск**. На планшетах и в альбомной ориентации (ширина ≥ 600 dp) — NavigationRail слева вместо нижней панели, а полный плеер делится на две колонки: обложка слева, контролы справа (WindowSizeClass).

Пустые состояния обязательны: «Музыка не найдена», «Ничего не найдено», «Плейлист пуст» — с иконкой и подсказкой.

## 5. Архитектура и структура проекта

Архитектура — MVVM с однонаправленным потоком данных: экраны читают `StateFlow` из ViewModel, ViewModel берёт данные из репозиториев, а плеером управляет только через `MediaController`.

&#91;embedded content: архитектура · UI, данные, воспроизведение\]

Главное правило: ExoPlayer создаётся один раз внутри `PlaybackService`, поэтому музыка переживает закрытие экрана и поворот устройства.

Структура пакетов:

```
com.localplayer.app/
├── LocalPlayerApp.kt          // @HiltAndroidApp
├── MainActivity.kt            // единственная Activity
├── data/
│   ├── model/                 // Track, Album, Artist, Folder, Playlist
│   ├── mediastore/            // MediaStoreSource, MediaStoreRepository
│   ├── db/                    // AppDatabase, DAO, Entity (плейлисты, счётчики)
│   ├── prefs/                 // SettingsRepository, SessionRepository (DataStore)
│   └── PlaylistRepository.kt
├── playback/
│   ├── PlaybackService.kt     // MediaSessionService + ExoPlayer
│   ├── PlayerConnection.kt    // обёртка над MediaController для UI
│   └── SleepTimer.kt
├── ui/
│   ├── theme/
│   ├── navigation/
│   ├── components/            // TrackRow, AlbumCard, MiniPlayer, EmptyState
│   └── screens/               // library, album, artist, folder, playlists, search, player, queue, settings, permission
└── di/                        // Hilt-модули
```

Данные в Room ссылаются на треки по id из MediaStore; сами метаданные треков в БД не дублируются.

## 6. Разрешения, фон и уведомления

Разрешения зависят от версии Android — просить только нужное для текущей версии.

| Разрешение | Android | Зачем |
| --- | --- | --- |
| `READ_MEDIA_AUDIO` | 13+ | Доступ к аудиофайлам |
| `READ_EXTERNAL_STORAGE` (`maxSdkVersion=32`) | 8–12 | Доступ к аудиофайлам |
| `POST_NOTIFICATIONS` | 13+ | Уведомление с контролами |
| `FOREGROUND_SERVICE` | все | Играть в фоне |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | 14+ | Тип foreground-сервиса |
| `WAKE_LOCK` | все | Не засыпать во время игры (через `setWakeMode` ExoPlayer) |

Интернет-разрешение не нужно и не добавляется.

Фоновое воспроизведение:

- `PlaybackService : MediaSessionService` владеет единственным ExoPlayer; в манифесте `android:foregroundServiceType="mediaPlayback"` и intent-filter `androidx.media3.session.MediaSessionService`.
- UI подключается к сервису только через `MediaController` — никогда не держать ExoPlayer в Activity/ViewModel.
- Уведомление с обложкой и контролами создаёт Media3 автоматически (DefaultMediaNotificationProvider); там же работают экран блокировки, кнопки наушников, Bluetooth, Android Auto-совместимые контролы.
- Аудиофокус: `setAudioAttributes(..., handleAudioFocus = true)` — пауза при звонке, приглушение при навигаторе.
- Отключение наушников: `setHandleAudioBecomingNoisy(true)` (настройка F22).
- При паузе и свайпе приложения из недавних — сервис останавливается (`onTaskRemoved`); при игре — продолжает работу.
- Позиция и очередь сохраняются в DataStore каждые 5 с, при паузе и смене трека (F12).

## 7. Нефункциональные требования и граничные случаи

Приложение должно быстро работать на библиотеке в 10 000 треков и не падать на «плохих» файлах.

Производительность:

- Холодный старт до первого экрана — до 1,5 с на среднем устройстве.
- Сканирование 10 000 треков — до 2 с, только на `Dispatchers.IO`.
- Списки — `LazyColumn`/`LazyVerticalGrid` со стабильными `key`, без подтормаживаний при прокрутке.
- Обложки — через `ContentResolver.loadThumbnail` (Android 10+) или embedded picture, с кэшем Coil и даунскейлом до размера элемента.
- Никаких операций с диском и БД на главном потоке (включить StrictMode в debug).

Граничные случаи, которые нужно обработать:

| Ситуация | Ожидаемое поведение |
| --- | --- |
| Нет тегов (название/исполнитель пустые или `<unknown>`) | Название = имя файла без расширения; исполнитель = «Неизвестный исполнитель» |
| Файл удалён, пока он в очереди или плейлисте | Пропустить, показать Snackbar; в плейлисте трек помечен серым |
| Битый или неподдерживаемый файл | `onPlayerError` → автопереход к следующему, не более 3 ошибок подряд, затем стоп |
| Разрешение отозвано в настройках | При возврате в приложение — экран запроса разрешения |
| Кириллица в тегах (в т.ч. старые MP3 в cp1251) | Доверять MediaStore; перекодировку оставить как TODO на позже |
| SD-карта извлечена | Треки с неё исчезают при перескане, играющий — как «файл удалён» |
| Поворот экрана, смена темы | Состояние и прокрутка сохраняются, музыка не прерывается |
| Система убила процесс | Восстановление по F12 |

Качество кода и доступность:

- Unit-тесты для репозиториев и ViewModel (JUnit + Turbine для Flow), фейковый источник MediaStore.
- У всех иконок-кнопок есть `contentDescription`; минимальная зона нажатия 48 dp.
- R8/minify включён для release; размер APK — цель до 10 МБ.

## 8. Этапы разработки и критерии приёмки

Работа идёт в 6 этапов; после каждого — сборка `assembleDebug` без ошибок, запуск на эмуляторе и короткий отчёт «что сделано / что проверить руками».

1. **Каркас.** Проект, Gradle, Hilt, тема Material 3, навигация с пустыми экранами, экран разрешения.
   - [ ] Приложение запускается, запрашивает нужное разрешение для своей версии Android
2. **Библиотека (F1–F7).** Репозиторий MediaStore, вкладки, сортировка, поиск, обложки.
   - [ ] На устройстве с музыкой видны все треки, альбомы, исполнители и папки; новый файл появляется без перезапуска
3. **Воспроизведение (F8–F12).** `PlaybackService`, `MediaController`, мини- и полный плеер, очередь, сохранение сессии.
   - [ ] Музыка играет при выключенном экране 30+ минут; контролы в шторке и на наушниках работают; звонок ставит на паузу
4. **Плейлисты и действия (F14–F19).** Room, избранное, автоплейлисты, меню «⋮», множественный выбор.
   - [ ] Плейлисты переживают перезапуск; удалённый файл не роняет приложение
5. **Настройки и таймер (F13, F20–F23).**
   - [ ] Таймер сна останавливает музыку с затуханием; тема меняется без перезапуска
6. **Полировка.** Адаптив под планшет, пустые состояния, анимации, иконка приложения, тесты, release-сборка.
   - [ ] Все случаи из раздела 7 проверены; `assembleRelease` собирается; тесты зелёные

MVP считается готовым, когда отмечены все 6 критериев и приложение проверено на телефоне и планшете (или эмуляторах Android 8, 12 и последней версии).

## 9. Будущие функции (не делать в MVP)

Эти идеи — для следующих версий; архитектура MVP не должна мешать их добавить.

- Эквалайзер и усиление басов (`android.media.audiofx`).
- Тексты песен из локальных `.lrc`-файлов с синхронной прокруткой.
- Виджет на рабочий стол (Jetpack Glance).
- Редактор тегов и обложек.
- Импорт / экспорт плейлистов в формате M3U.
- Crossfade между треками и ReplayGain-нормализация громкости.
- Полная поддержка Android Auto (браузинг библиотеки через `MediaLibraryService`).
- Английская локализация.
